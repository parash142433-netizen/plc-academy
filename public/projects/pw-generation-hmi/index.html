Build an operator panel for a purified water plant, step by step

In this tutorial you build the HMI for a purified water (PW) generation plant on a 12-inch SIMATIC Comfort panel connected to an S7-1500. You build it from four standard faceplates, draw the P&ID screens, configure six PID loops, the softener regeneration screen, the RO sequence, alarms, trends and user rights. The last steps test the project, and a simulator runs the finished panel against a model of the plant.

Build steps
    Understand

    Start with the water, not the panel

    A PW generation plant turns raw water into purified water for pharmaceutical use, and proves it continuously with conductivity. Water that is not good enough never reaches the storage tank: it goes to drain. The HMI's job is to let the operator run that plant, see at a glance whether the water is good, and react before the tank runs dry.

    Engineer's thinking

    What proves the water is good?
    Conductivity after each RO pass. RO-2 permeate (QE-315) must stay below 1.3 µS/cm, or the water is dumped. That one number is the most important value on the panel.
    Why does pH matter?
    At low pH, carbon dioxide passes straight through the membranes and spoils the conductivity. Dosing NaOH to pH 8.0 turns it into bicarbonate, which the RO rejects. An empty NaOH tank therefore ends in dumping, and the operator should see that chain.
    What runs by itself?
    Almost everything: six PID loops, the softener regeneration, dumping and recycling. The operator starts and stops the plant, watches, and acts on alarms. Supervisors tune; administrators maintain.
    Why so many identical devices?
    Fourteen analog values, five motors, three valves, six loops. Building each one by hand would be slow and inconsistent. Four faceplates (step 5) do it once.

    Engineer's thinking

    Why pop-ups instead of a screen per device?
    The operator keeps the P&ID in view while operating one pump. A pop-up opens over the process, and closes back to it.
    What are slide-in screens for?
    A slide-in screen drops in from an edge on a swipe or button: a good place for the main menu or a quick status strip, without stealing space from the P&ID.

    Robustness habits

    • Name every tag after its instrument: type letters, then area and loop (PIT-111, FIC-314). The faceplate shows the same name the P&ID drawing uses.
    • Write commands as pulses the PLC resets. A lost connection then never leaves a "start" set.
    • Give each object a Visible bit, so one screen layout serves plants with and without a device.
    Build

    Build the faceplate types

    A faceplate type is a reusable screen object in the project library. Build one per standard object, give it an interface that takes the device's data structure, and drop an instance on the screen for every device. Change the type once, and every instance updates.

    1. In the project library, create a faceplate type Motor. Add an interface property Device of the motor's PLC data type, plus Name.
    2. Draw the faceplate inside the type: name, state text, speed, Auto/Manual buttons, Start/Stop buttons. Bind each object to an interface member.
    3. Animate it with the status word: green when running, red when faulted, dashed outline in manual.
    4. Repeat for Analog, Valve and PID, then release the types.
    5. For each device, create a pop-up screen with one faceplate instance, and on the P&ID symbol's Click event call ShowPopupScreen with that pop-up.

    AnalogPV, unit, range bar, limits, raw valueLimits; simulationSupervisor; administrator
    MotorState, speed, modeAuto/manual, start/stopSupervisor
    ValveOpen/closed, modeAuto/manual, open/closeSupervisor

    A faceplate is not a function block

    Keep logic out of the faceplate. If a manual start needs an interlock, the PLC enforces it and reports it in the status word. A faceplate that only shows and requests can never disagree with the PLC.

    Robustness habits

    • Grey for normal, colour for state and abnormal (ISA-101). A screen full of green tells the operator nothing.
    • Always show the unit beside the value. "1.3" means nothing; "1.3 µS/cm" does.
    • Keep the same left-to-right flow on every process screen.

    Analog values: scaling, limits and simulation

    An S7-1500 analog input delivers 0 to 27648 for 4 to 20 mA. The PLC scales it with the object's range, compares it with four limits and sets four status bits. The HMI shows the result, lets a supervisor adjust the limits, and lets an administrator replace the reading with a simulated value for testing.

    Simulation must be impossible to forget

    A simulated pressure looks exactly like a real one. Show an "S" badge on every simulated value, raise a warning alarm while any simulation is active, and give the right only to administrators.

    • Switching to manual never starts or stops anything by itself; the device keeps its state until the next command (bumpless).

    Six loops keep the plant steady. Each gets the same PID faceplate and its own screen with a trend. Supervisors change set points and tuning; the PLC runs the controllers.

    QIC-202NaOH dosing pump strokeRO-1 feed pH QE-202pH 8.0Reverse
    FIC-213Concentrate valve CV-213RO-1 concentrate flow FIT-2131.0 m³/hReverse
    FIC-314P-210 speedProduct flow FIT-3143.0 m³/hReverse
    PIC-312P-310 speedStage 2 inlet pressure PIT-3122.0 barDirect

    Engineer's thinking

    Why is PIC-312 direct acting?
    It measures the pressure between the two passes. Speeding up P-310 pulls that pressure down. When the pressure is too high, the output must rise, the opposite of the other loops. Get the action wrong and the loop runs away at full speed.
    What happens when switching to manual?
    The output stays where it was (bumpless), and the faceplate lets the supervisor move it by hand. Back in auto, the controller takes over from that output.
    Why limit the output?
    LMN_LLM and LMN_HLM keep a VFD above its minimum speed and a dosing pump below a safe stroke, whatever the controller wants.

    Regeneration needs salt

    Without brine, the injection step regenerates nothing, yet the timer would happily count down. Make the salt tank level a regeneration permissive: the sequence waits at injection, and the operator sees why.

    The RO sequence: start, dump and recycle

    The PLC runs the plant as a small state machine. The HMI shows the state, offers Start and Stop, explains a refused start, and lets a supervisor set the limits and timers that drive the transitions.

    SettingExampleEffect
    RO-1 conductivity dump limit (QE-214)20 µS/cmAbove it for 10 s: dump
    RO-2 conductivity dump limit (QE-315)1.3 µS/cmAbove it for 10 s: dump; below for 20 s: fill again
    Raw water pressure low set point (PT-101)1.2 barBelow it: trip and start refused
    Recycle on / off timers30 / 60 minTank full: recycle 30 min, rest 60 min, repeat

    Engineer's thinking

    Why delays on dumping?
    A conductivity spike of a few seconds is normal after a start. Without the 10 s delay the valves would chatter. Without the 20 s "good" time, the first good reading after a bad spell would already go to the tank.
    Why recycle at all?
    Membranes do not like standing still. Recycling to the RO-1 feed keeps water moving through them while the tank is full, and the off timer saves energy.
    What do AUTO, SEMI AUTO and MANUAL mean?
    AUTO runs the whole state machine. SEMI AUTO lets the operator start the stages one by one. MANUAL hands every device to its faceplate. The panel shows the mode on every process screen.

    Alarms and the alarm log

    Two classes are enough. Errors stop the plant and must be acknowledged. Warnings tell the operator something needs attention and clear themselves when it is fixed. Every text starts with the instrument tag, so the operator knows where to look.

    Alarm textClassSource
    (PT-101) Raw water pressure low - plant stoppedErrorsAnalog status bit L + trip
    (P-210) High pressure pump 1 trippedErrorsMotor status bit Fault
    (QE-315) RO-2 conductivity high - dumpingWarningsSequence state DUMPING
    (QE-214) RO-1 conductivity high - dumpingWarningsSequence state DUMPING
    (QE-202) RO-1 feed pH lowWarningsAnalog status bit L
    (LSA-204) NaOH dosing tank level lowWarningsLevel switch
    (LSA-131) Salt tank level low - regeneration blockedWarningsLevel switch
    1. Create discrete alarms on the PLC's alarm words, one bit per alarm, with the text and class above.
    2. Place the alarm view on the Alarm screen and an alarm indicator in the template; acknowledgement writes ALM_ACK, which the PLC uses to reset its latches.
    3. Create the alarm log PW_GEN_ALARM_LOG on the storage card and assign both classes to it. The Alarm log screen shows it.

    Robustness habits

    • Alarm on the cause, not every consequence. An empty NaOH tank should raise one warning, then the dumping warning, not twenty analog limit alarms.
    • Keep trip alarms latched until acknowledged, so a short dip that stopped the plant is never invisible.
    • Write the alarm-bit table with the PLC programmer; S7 words are byte-swapped, so test every bit once.

    • Give every set point an input range in the I/O field: the panel refuses a dump limit of 0 before the PLC ever sees it.

      What is real and what is modelled

      • As configured in the tutorial: the screens, faceplates, authorizations, the plant states and their transitions, the dump limits and recycle timers, the softener sequence, the alarm texts and classes.
      • Modelled: the water. Pressures, flows, pH and conductivity come from simple first-order models chosen so the loops and limits behave realistically, not from membrane design data.
